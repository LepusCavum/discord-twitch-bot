# Planned Folder Structure (WIP)

Status: Draft

This document describes the intended source and test layout. GitHub milestones and user stories define what must be delivered for v1.0; this document only records where implementation belongs. Update the status column when a successful PR changes the structure.

## Conventions

- Use repository-relative paths.
- Use one type per file unless a small private implementation is local to its owner.
- Keep application-owned interfaces and models at the application boundary; third-party types stay inside adapters.
- Keep tests parallel to production feature folders.
- Use status values `Existing`, `Planned`, and `Needs decision`
